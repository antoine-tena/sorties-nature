Presentation orale - repartition detaillee

Nathan

- nom du projet : INFO633-Sorties
- objectif : gerer des sorties nature dans une application web
- exemples : randonnee, velo, ski, trail
- besoin principal : centraliser les informations utiles sur une sortie
- actions possibles : consulter, ajouter, modifier, supprimer
- architecture generale : front HTML/CSS/JavaScript + backend PHP/Apache + base MySQL
- outil de lancement de la base : Docker Compose
- idee a faire passer : application simple en apparence, mais avec vrai backend et vraie base de donnees
- transition : presentation du fonctionnement, puis de la technique, puis bilan


Antoine

- entite principale : la sortie
- donnees stockees pour une sortie : titre, description, type, difficulte
- autres donnees : distance, denivele positif, chiens autorises, visibilite publique
- geolocalisation : latitude + longitude du point de depart
- fichier GPX : upload depuis le formulaire
- stockage GPX : fichier conserve dans uploads, chemin stocke en base
- avantage de ce choix : ne pas stocker directement le fichier dans MySQL
- table types_sortie : normaliser les categories de sorties
- exemples de types : randonnee pedestre, velo/VTT, ski/raquettes, trail
- interet : eviter les valeurs incoherentes et garder des donnees propres
- realisations : historique des sorties effectuees
- donnees d'une realisation : date + commentaire
- logique metier : une meme sortie peut etre realisee plusieurs fois
- fonctionnalites API : CRUD sorties
- autres fonctionnalites API : CRUD realisations
- fonctions supplementaires : liste des types, export JSON, import JSON, statistiques


Pavel

- serveur web : PHP + Apache
- role du serveur : exposer une API JSON sous /api et servir les fichiers statiques du dossier frontend/public
- principales routes sorties : GET /api/sorties, GET /api/sorties/:id, POST /api/sorties, PUT /api/sorties/:id, DELETE /api/sorties/:id
- meme principe pour les realisations : routes dediees
- connexion base de donnees : PDO MySQL
- gestion des connexions : connexion singleton centralisee dans backend/shared/db.php
- interet de cette approche : une configuration unique et reutilisable pour toutes les routes
- tables principales : types_sortie, sorties, realisations, stats_eco
- relations SQL : cle etrangere entre sorties et types_sortie
- autres relations SQL : cle etrangere entre realisations et sorties
- effet important : suppression en cascade des realisations si une sortie est supprimee
- logique SQL supplementaire : trigger sur insertion d'une sortie
- role du trigger : mettre a jour automatiquement un compteur dans stats_eco
- lancement du projet : docker compose up -d --build
- initialisation de la base : script backend/database/schema.sql execute au premier lancement Docker
- competences mobilisees : schema relationnel, API REST, formulaires, upload, SQL, Docker
- ameliorations possibles : tests automatises, filtres plus avances, meilleure exploitation des traces GPX

Conclusion a dire ensemble

- application web de gestion de sorties nature
- combinaison de plusieurs couches : interface, backend, base MySQL
- notions mises en pratique : modelisation des donnees, API, persistance, contraintes SQL, Docker
- projet simple a utiliser mais complet techniquement
