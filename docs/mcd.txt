BDD Sorties Natures - informations pour MCD

Nom de la base
- sorties_natures

Entite : UTILISATEUR
- id : INT, PK, auto increment
- nom : VARCHAR(100), obligatoire
- email : VARCHAR(190), obligatoire, unique
- mot_de_passe_hash : VARCHAR(255), obligatoire
- date_creation : TIMESTAMP, valeur par defaut CURRENT_TIMESTAMP

Entite : TYPE_SORTIE
- id : INT, PK, auto increment
- nom : VARCHAR(100), obligatoire, unique

Entite : SORTIE
- id : INT, PK, auto increment
- titre : VARCHAR(150), obligatoire
- description : TEXT, facultatif
- id_type_sortie : INT, FK vers TYPE_SORTIE.id, facultatif
- difficulte : VARCHAR(50), facultatif
- distance : DECIMAL(8,2), facultatif
- denivele_positif : INT, facultatif
- chien_autorise : TINYINT(1), defaut 1
- trace_gpx : VARCHAR(255), facultatif
- latitude : DECIMAL(10,7), facultatif
- longitude : DECIMAL(10,7), facultatif
- is_public : TINYINT(1), defaut 1
- date_creation : TIMESTAMP, valeur par defaut CURRENT_TIMESTAMP

Entite : REALISATION
- id : INT, PK, auto increment
- id_sortie : INT, FK vers SORTIE.id, obligatoire
- date_realisation : DATE, obligatoire
- commentaire : TEXT, facultatif

Entite : STATS_ECO
- label : VARCHAR(100), PK
- valeur : INT, defaut 0

Relations
- TYPE_SORTIE 1 ---- 0..n SORTIE
- Une sortie appartient a zero ou un type
- Un type peut etre associe a plusieurs sorties

- SORTIE 1 ---- 0..n REALISATION
- Une realisation appartient obligatoirement a une sortie
- Une sortie peut avoir zero, une ou plusieurs realisations

Contraintes SQL
- FK SORTIE.id_type_sortie -> TYPE_SORTIE.id
- ON UPDATE CASCADE
- ON DELETE SET NULL

- FK REALISATION.id_sortie -> SORTIE.id
- ON UPDATE CASCADE
- ON DELETE CASCADE

Regles metier visibles dans la BDD
- le type de sortie est normalise dans une table separee
- une sortie peut exister sans type associe si le type est supprime
- une sortie peut etre realisee plusieurs fois
- une realisation n'existe pas sans sortie
- un email utilisateur ne peut exister qu'une seule fois

Trigger
- nom : incrementer_stats_sorties
- table concernee : sorties
- moment : AFTER INSERT
- effet : incremente la valeur du label nb_total_sorties dans stats_eco

Donnees de demo prevues dans backend/database/schema.sql
- types de sortie : Randonnee pedestre, Velo / VTT, Ski / Raquettes, Trail
- 1 utilisateur demo : demo@sorties.local / mot de passe demo1234
- 10 randonnees de demonstration autour d'Annecy et des massifs proches
- plusieurs realisations exemples associees a certaines sorties

Remarque MCD
- STATS_ECO est une table technique, pas forcement indispensable dans un MCD conceptuel
- mot_de_passe_hash est un attribut technique de UTILISATEUR
- si tu veux un MCD purement metier, les entites principales a garder sont : UTILISATEUR, TYPE_SORTIE, SORTIE, REALISATION
